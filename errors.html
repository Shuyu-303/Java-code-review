Errors

Every programmer writes broken code. Knowing which kind of error you have is the fastest way to fix it.

Types of Errors

TypeWhen it happensTypical symptom
SyntaxWhile compilingThe program will not compile.
RuntimeWhile runningThe program crashes with an exception.
LogicWhile runningIt runs, but gives the wrong answer.
Note: syntax errors are the easiest - the compiler points at them. Logic errors are the hardest - nothing complains; you must reason and test.

Syntax Errors

A syntax error breaks the grammar rules of Java. The code cannot compile, so the compiler reports the line and what it expected.

Fix: read the compiler message - it tells you the file and line number, even if the real mistake is on the line just before.

Runtime Errors

The code compiles, but something goes wrong while it runs - often an exception that stops the program.

The program prints a stack trace - read the first line to see the exception and the message, and the following lines to see where it happened.

Logic Errors

The program compiles and runs without crashing, but does the wrong thing. The mistake is in your reasoning, not the syntax.

Debugging

Debugging is the process of finding and fixing errors. Simple techniques first, tools later.

  1. Print statements - print values at key points to see what is really happening.
  2. Read the error message - the exception type and line number are clues, not noise.
  3. Rubber-duck test - explain the code out loud, line by line.
  4. Isolate - comment sections out to narrow down where it breaks.
  5. Use the IDE debugger - set breakpoints and step through line by line.
Tip: a bug you can reproduce is already half solved - find the smallest input that triggers it, then investigate from there.
